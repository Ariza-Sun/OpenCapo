# 前端计划：Discord Bot（阶段 1）

> 对应需求：`docs/REQUIREMENTS.md` 第 5.4 / 5.5 / 5.6 节。本文档回答"在 Discord 上怎么做"。
> 状态：草稿，随需求讨论更新。

## 1. 前提与边界

- 阶段 1 只用 Discord **原生组件**：斜杠命令、附件、消息、嵌入（embed）、按钮、下拉菜单（select）、弹窗（modal）、图片 / 文件附件。
- 不做 Discord Activity（内嵌网页），不做外链网页。
- 由此不做：同步播放、拖拽编辑、波形 / 频谱、语音频道播放。

## 2. 安装方式

| 方式 | 说明 | 决定 |
|---|---|---|
| 服务器安装（Guild Install） | 管理员把 Bot 加进服务器，成员在频道里用 | 支持 |
| 用户级安装（User Install） | 用户把 Bot 装到自己账号下，在私信或任何服务器里用，无需管理员 | 支持 |

两种安装共用同一套命令；用户级安装时谱子消息发在私信或当前频道（受该频道权限约束）。

## 3. Discord 硬约束与应对

| 约束 | 数值 | 应对 |
|---|---|---|
| 附件大小 | 免费用户每个附件约 10 MB（Discord 改过几次，以当前官方文档为准；服务器加成后更高） | 实际输入格式限于 mp3 / m4a / ogg / opus；4 分钟 128 kbps mp3 约 4 MB。wav / flac 超限时给出明确提示（"请转成 mp3"） |
| 交互必须 3 秒内应答 | | 立即 defer，回"已收到，排队中 / 处理中，预计 N 分钟" |
| 交互令牌有效期 | 15 分钟 | 单曲全流程目标 < 5 分钟；超过 15 分钟时改用普通频道消息 / 私信发送结果（需要发消息权限） |
| 下拉菜单 | 每个最多 25 项 | 指法调 ≤ 12 项；节奏型控制在 25 以内，超出则先选分类再选节奏型 |
| 弹窗 | 最多 5 个文本框，每框 4000 字 | 粘贴歌词、改和弦够用 |
| 按钮 | 每条消息最多 25 个（5 行 × 5） | 够 |
| 消息长度 | 2000 字 / 嵌入 6000 字 | ChordPro 文本超长时改为附件 |
| 消息编辑频率 | 有限流 | 每次用户操作只编辑一次消息 |
| Bot 回传附件 | 同样受上限 | PNG / PDF / MusicXML / MIDI / JSON 均很小 |

## 4. 命令

| 命令 | 参数 | 行为 |
|---|---|---|
| `/transcribe` | `audio`(附件, 必填)、`title`、`artist`、`lyrics`(可选文本) | 校验 → 入队 → 回执（队列位置、预计时间）→ 完成后发"谱子消息" |
| `/status` | | 列出自己排队中 / 处理中的任务 |
| `/import` | `project`(JSON 附件) | 载入之前导出的项目，重新生成谱子消息 |
| `/delete` | | 删除自己在服务端的全部数据 |
| `/help` | | 用法、限制、配额 |

也支持：对一条带音频附件的消息使用"消息右键 → 应用 → Transcribe"（Message Command），省去重新上传。

命令名与所有文案提供中 / 英两套，按用户的 Discord 语言设置选择；命令本身通过 Discord 的本地化字段注册。

## 5. 谱子消息（核心界面）

一条消息，由 Bot 发送并在之后每次调整时**编辑这同一条消息**（不刷屏）。

### 5.1 内容

- 附件：谱子第一页 PNG（预览）；多页时附完整 PDF。
- 嵌入：歌名 / 艺术家、原曲调、当前指法调与变调夹（"G 调指法，夹 3 品"）、BPM、拍号、低置信和弦数量提示（"有 4 个和弦置信度较低，已在谱上标出"）、当前版本号。

### 5.2 控件

| 控件 | 类型 | 行为 |
|---|---|---|
| 指法调 | 下拉 | 每项显示"X 调指法（夹 N 品）"，按品数升序；> 7 品的排后并加"不推荐"。选后重渲染 |
| 节奏型 | 下拉 | 含"无"；选后重渲染 |
| 简化和弦 | 按钮（开 / 关，显示当前状态） | 切换后重渲染 |
| 改和弦 | 按钮 → 弹窗 | 见 6.1 |
| 换指法 | 按钮 → 下拉（和弦）→ 下拉（候选按法） | 选后重渲染 |
| 歌词 | 按钮 → 弹窗 | 见 6.2 |
| 更多 | 按钮 → 第二组控件 | 变调夹覆盖、速度 / 拍号、改简谱（避免首屏超过 25 个控件） |
| 导出 | 下拉 | PDF / PNG 全页 / MusicXML / MIDI / ChordPro / 项目 JSON；选后以附件回复 |
| 恢复上一版 | 按钮 | 回退到上一版本并重渲染；保留最近 20 版 |

### 5.3 权限

- 谁能操作控件：**[待定]** 建议发起者 + 该频道有"管理消息"权限的成员。其他人点击时得到仅自己可见的提示："这张谱由 @X 发起；你可以用 `/transcribe` 生成自己的一份。"
- 用户级安装、私信场景：只有发起者。

## 6. 弹窗设计

### 6.1 改和弦

一个多行文本框，每行一条指令：

```
12.1 = Am7          # 第 12 小节第 1 拍起改为 Am7
12.3 = G/B          # 第 12 小节第 3 拍起改为 G/B
all Cmaj7 -> C      # 全曲 Cmaj7 替换为 C
```

- 小节 / 拍编号与谱上一致（谱上每行行首标小节号）。
- 和弦名接受常见写法（Am7、A-7、Amin7 都认），解析失败时回显哪一行有问题，其余照常应用。
- 这也是"改和弦边界"的入口：在某一拍写一个和弦就等于在那一拍换和弦。

### 6.2 歌词

一个多行文本框，预填当前歌词全文（按行）。用户粘贴 / 修改后提交，系统重新对齐、重渲染。

### 6.3 变调夹覆盖

一个文本框：品数（0–12）。覆盖后指法调跟着重算并在嵌入里标注"手动"。

### 6.4 速度 / 拍号

两个文本框：BPM、拍号（如 4/4、3/4、6/8）。

### 6.5 改简谱（P1）

一个多行文本框，每行一个小节：

```
12: 3 5 3 6 | 6 5 - -      # 简谱音级，- 延音，0 休止，下划线用 _ 表示八分
```

具体语法待定，原则是能在手机上打出来。

## 7. 任务生命周期与文案

```
/transcribe
  ├─ 校验失败 → 仅自己可见的错误：格式不支持 / 超过 10 MB / 超过 10 分钟 / 今日配额已用完
  ├─ 入队 → 回执："已收到《xxx》，前面还有 N 首，预计 M 分钟。完成后会在这里通知你。"
  ├─ 处理中 → （可选）每个大环节更新一次回执："正在分轨… / 识别和弦… / 对齐歌词… / 排版…"
  ├─ 成功 → 发谱子消息，并 @发起者
  └─ 失败 → "处理失败：<原因>"，原因枚举：超时 / 未检测到人声（歌词与简谱为空，但和弦谱照出）/ 音频损坏 / 服务异常（附任务 ID 便于反馈）
```

超过 15 分钟（交互令牌过期）时，结果改为普通频道消息发送；若 Bot 在该频道没有发消息权限，则私信发起者。

## 8. 与后端的接口（前端需要什么）

| 接口 | 输入 | 输出 |
|---|---|---|
| 提交任务 | 音频文件、歌名、艺术家、歌词（可选）、用户 ID、来源（guild / DM）、语言 | 任务 ID、队列位置、预计时间 |
| 任务状态 | 任务 ID | 排队 / 处理中（当前环节）/ 成功 / 失败（原因） |
| 获取项目 | 项目 ID | 结构化结果 + 当前编配参数 + 版本列表 |
| 渲染 | 项目 ID、版本、编配参数（指法调、节奏型、简化、变调夹覆盖…） | PNG 第一页、PDF |
| 应用编辑 | 项目 ID、编辑指令（改和弦 / 歌词 / 指法 / 速度 / 简谱） | 新版本号 + 渲染结果 |
| 回退 | 项目 ID | 上一版本号 + 渲染结果 |
| 导出 | 项目 ID、格式 | 文件 |
| 导入 | 项目 JSON | 项目 ID |
| 删除用户数据 | 用户 ID | 确认 |
| 配额查询 | 用户 ID、guild ID | 剩余次数 |

渲染与编辑接口必须秒级返回（不触发模型推理）。

## 9. 技术选型 **[待定]**

| 项 | 候选 | 倾向 |
|---|---|---|
| Bot 框架 | discord.py（Python，与核心库同语言）/ discord.js（Node） | **[建议]** discord.py，减少语言栈 |

## 10. 开放问题

1. 控件操作权限（见 5.3）。
2. 节奏型库的分类方式（按拍号？按风格？）决定下拉是一级还是两级。
3. 改简谱的文本语法。
4. 是否在处理中逐环节更新回执（多几次消息编辑 vs 更好的等待体验）。
5. 公共实例的 Bot 名称、头像、`/help` 里的服务条款文案。
