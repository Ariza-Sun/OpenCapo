# OpenCapo 需求文档（阶段 1）

> 版本：v0.4（定稿）。本文档只描述**做什么、做到什么程度**；实现方案见 `docs/plans/`。
> 只覆盖阶段 1，阶段 1 不做的功能统一放在第 10 节"后续开发"。
> 阶段 1 需求级决策已全部定稿，不再含 **[待定]** / **[建议]** 项。实现层面的开放问题在 `docs/plans/` 各文档末尾。

## 1. 背景与目标

市面上的"听歌扒谱"工具（Capo、Lamucal、Chordify、Moises）都是闭源收费产品。国内吉他谱平台的弹唱谱全靠人工编配，覆盖不到的歌（尤其是英文歌）就没有谱。

OpenCapo 的目标：

- 用户上传一首歌的音频，几分钟后得到一张**吉他弹唱谱**：和弦图 + 六线谱节奏型 + 简谱 + 歌词。谱子采用简谱式弹唱谱排版，**中文 / 英文歌曲均支持**。
- 用户可以调整指法调、节奏型、和弦，粘贴歌词重新对齐，导出 PDF / 图片 / MusicXML。
- 通过 **Discord** 交付，零安装；代码开源，任何人可自部署；我们运营一个公共实例。

## 2. 范围边界

### 阶段 1 包含
- 音频输入 → 分析（分轨、节拍、和弦、调性、人声旋律、歌词）→ 编配 → 四层弹唱谱 → 导出。
- 基于 Discord 原生组件的查看、调整、编辑、导出。
- 公共实例的排队、配额、数据保留。

### 明确不做
- 本地运行的桌面 / 命令行软件。
- 段落结构自动检测（intro / verse / chorus）。
- AI 翻唱 / 换声。
- 向用户提供分轨音频或任何变速 / 变调后的音频；分轨只作内部中间产物。
- 歌曲库、社区分享、账号体系、付费墙。
- 内嵌网页（Discord Activity）或外链网页。由此接受：**没有光标跟随音频的同步播放，没有拖拽式编辑，没有波形 / 频谱交互**。这些放在第 10 节。

## 3. 目标用户与场景（已定）

**目标用户：吉他弹唱者。**

| 场景 | 阶段 1 给什么 |
|---|---|
| 听到一首歌想马上弹唱 | 一张弹唱谱：和弦图 + 节奏型 + 简谱 + 歌词，按自己顺手的指法调出谱 |
| 在 Discord 吉他群里一起扒谱、互相纠错 | 谱子直接显示在频道里，可调整、改完重新出图 |

不以键盘手、尤克里里、贝斯、乐队排练为目标用户；他们能用则用，不为他们做专门功能。

## 5. 功能需求

```
音频 ──▶ 分析 ──▶ 结构化结果 ──▶ 编配 ──▶ 弹唱谱 ──▶ 导出
                                    ▲              │
                                    └── 用户调整 ◀──┘
```

**最终产物（已定）**：一张吉他弹唱谱，样式以 `docs/reference/desperado-sheet.webp` 为默认排版标准。从上到下四层：和弦图、六线谱（节奏型 / 指法）、简谱（人声旋律）、歌词（音节级对齐）；页眉含歌名、速度、调号（1=X）、拍号、变调夹提示。

"分析"是**转录**（忠实记录原曲有什么），"编配"是**设计**（根据和弦和节拍生成人能弹的伴奏），两者分开建模。

### 5.1 输入（已定：音频）

| 项 | 要求 |
|---|---|
| 来源 | 用户上传的音频文件 |
| 格式 | mp3 / m4a / ogg / opus / wav / flac；受交付渠道的附件大小限制（见前端计划） |
| 时长 | **已定**：上限 8 分钟；超过提示用户裁剪 |
| 声道 / 采样率 | 任意 |
| 歌名 / 艺术家 | 可选，用于谱子页眉；未填则用文件名 |
| 歌词文本 | 可选；提供时跳过识别、只做对齐 |

### 5.2 分析输出（数据模型）

所有结果带时间戳（秒），与原音频对齐。

| 对象 | 字段 | 已定内容 |
|---|---|---|
| `Beat` | time, is_downbeat, bar_index, beat_in_bar | 做到小节 + 拍 |
| `Tempo` | bpm（全局） | 只要全局 BPM，不做局部速度曲线；单位是每分钟多少个 `Beat` |
| `TimeSignature` | numerator, denominator | 拍号。numerator = 每小节拍数（由强拍间距推出）；denominator 默认 4，每小节 6 拍记为 6/8。约定一个 `Beat` 对应一个 denominator 音符时值，`Note` 的拍网格与 BPM 都以此为单位。3/4 与 6/8 的自动区分不可靠，按上述规则记录 |
| `Key` | tonic, mode(major/minor), 置信度 | 做。简谱的 1=X 和变调夹换算都依赖它 |
| `Chord` | start, end, root, quality, bass（转位）, 置信度 | 见下 |
| `Note`（人声旋律） | start, end, pitch(MIDI), 量化后的位置与时值（start_tick、duration_ticks，以拍网格为单位）；附点、连音线、三连音在渲染时推出 | 只做人声旋律；必须到音符并量化到拍网格，供简谱渲染 |
| `LyricSyllable` | start, end, text, line_index, note_ref | 中、英；音节级对齐（英文按音节拆 Des-pe-ra-do，中文一字一音），每个音节挂到一个音符 |
| `Stem` | 音频 × {vocals, drums, bass, other} | **内部中间产物**，用于提升歌词、和弦、节拍、旋律识别的准确率；处理完成后删除，不对用户提供 |

**和弦（已定）**：
1. 覆盖面向 Capo 看齐：根音 12 种；性质至少覆盖大、小、7、maj7、min7、6、m6、sus2、sus4、5、dim、aug 等 14 种；**必须支持转位**（如 D/F#、G/B）。
2. 每个和弦带置信度，低置信的在谱上用不同样式标出，提醒复核。
3. 和弦边界对齐到拍网格：先检测节拍，再在拍 / 小节网格上标和弦。

**旋律 + 歌词的预期**：这两项技术上最难（人声滑音 / 颤音切成离散音符有损；音节对到音符两边都可能错）。原则是 **AI 出初稿，人来改**。歌词提供"粘贴歌词文本、系统只做对齐"模式；不做自动联网抓歌词（版权）。

### 5.3 编配（已定）

| 项 | 规则 |
|---|---|
| 演唱调 | 默认等于原曲调。用户唱不上去 / 唱不下来时可升 / 降若干半音（或直接选一个调）。改演唱调后指法调选项与变调夹重新计算 |
| 指法调与变调夹 | 在当前演唱调下，用户**只选指法调**（C / G / D / A / E 等好按的调），系统按 `变调夹品数 = 演唱调 − 指法调` 算出夹几品，给出该指法调下的和弦名与和弦图。品数 > 7 的选项排后 / 标灰；算出负数的指法调不可选。保留手动覆盖变调夹与任一和弦 |
| 页眉标记 | 同时显示**原调、演唱调、指法调 + 变调夹品数**（如"原调 G · 演唱调 F · E 调指法 夹 1 品"）。简谱 `1=X` 写演唱调。简谱数字与节奏型不随调变化；和弦名按指法调书写 |
| 和弦指法 | 每个和弦给一个默认按法，用户可换 |
| 节奏型 | **可选**：默认按速度 / 拍号推荐一个，用户可从节奏型库换，也可选"无"（六线谱行只显示和弦变化点） |
| 前奏 / 间奏 | **留空**，不做乐器旋律转录 |
| 简谱 | 由人声 `Note` + `Key` 渲染为音级（1–7，高低点）+ 时值记号（下划线、附点、连音线、休止） |
| 简化和弦显示 | 开关：把 Cmaj7 显示为 C、G/B 显示为 G 等，底层数据不变 |

### 5.4 交互需求

交付渠道为 Discord，具体命令与控件设计见 `docs/plans/frontend-discord.md`。这里只规定用户必须能做到什么：

| 需求 | 说明 |
|---|---|
| 发起分析 | 上传音频（可附歌名、艺术家、歌词），得到回执和预计等待时间 |
| 查看进度 | 知道自己任务在排队 / 处理中 / 失败及原因 |
| 查看谱子 | 在聊天界面里直接看到谱子预览，不必下载 |
| 调整 | 只保留**不需要乐理就能点的**：升 / 降演唱调、选指法调、换节奏型、简化和弦开关、粘贴歌词；每次调整后看到更新后的谱子 |
| 精修 | 逐个和弦、指法、简谱音符的修改**不在 Discord 里做**；导出 MusicXML 到 MuseScore / Guitar Pro 等专业软件精修 |
| 导出 | 选格式后得到文件 |
| 协作 | 同一张谱在群里对所有人可见；**已定：只有发起任务的人能调整**。其他人想改，自己发起一份 |
| 多语言 | 界面文案中 / 英，跟随用户语言设置 |
| 响应 | 调整类操作秒级返回（不重跑模型）；分析类操作分钟级，见第 7 节 |

### 5.5 调整能力（已定：只做简单的）

原则：面向没有乐理基础的爱好者，前端保持简单。所有调整都是"选一个选项"或"贴一段文字"，不需要知道小节号、和弦名、音符时值。有能力改单个和弦的人，导出到专业软件去改。

| 功能 | 形式 | 优先级 |
|---|---|---|
| 升 / 降演唱调 | 选项 | P0 |
| 选指法调（默认由系统选最好按的） | 选项 | P0 |
| 简化和弦开关 | 开关；默认开 | P0 |
| 换 / 去掉节奏型 | 选项 | P0 |
| 粘贴歌词并重新对齐 | 粘贴文本 | P0 |
| 重置为初始结果 | 按钮 | P1 |

不做（移至第 10 节）：改单个 / 多个和弦、批量替换、改和弦边界、换和弦指法、手动覆盖变调夹、改 BPM / 拍号、改简谱音符、版本历史与回退。

### 5.6 导出

| 格式 | 内容 | 优先级 |
|---|---|---|
| PNG（预览 + 全页） | 默认排版的四层谱 | P0 |
| PDF | 同上，多页 | P0 |
| MusicXML | 五线谱 + 六线谱 + 和弦符号 + 歌词音节，可导入 MuseScore / Guitar Pro 精修。**这是精修的唯一出口，因此 P0** | P0 |

**已定：只导出这三种。** 不做 MIDI、ChordPro、项目 JSON；不导出分轨音频、变速 / 变调后的音频。

### 5.7 阶段 1 内的里程碑（已定）

| 里程碑 | 内容 | 验收 |
|---|---|---|
| M1 三层谱 | 上传 → 和弦图 + 六线谱节奏型 + 歌词（粘贴对齐优先，识别其次）；演唱调 / 指法调 / 节奏型 / 简化；导出 PDF、PNG、MusicXML | 任意 mp3 几分钟内得到一张能弹的谱；MusicXML 在 MuseScore 里可打开并改和弦 |
| M2 四层谱 | 加人声旋律 → 简谱行 + 歌词音节挂到音符；MusicXML 含旋律与歌词 | 简谱行与歌词对齐 |

## 6. 差异化（竞品没有的）

已定：
- **简谱式弹唱谱（简谱 + 六线谱 + 歌词）一键生成，中 / 英文歌曲均支持**。四家竞品都不出简谱，国内平台靠人工且基本不覆盖英文歌。最大差异点。
- **Discord 原生**：零安装，群里直接出谱、群成员协作纠错。
- **选指法调而不是选变调夹**。
- **和弦置信度**：低置信和弦在谱上标出。
- **简化和弦开关**。
- **粘贴歌词对齐模式**。
- **开源 + 可自部署 + 导出全部免费**。

## 7. 非功能需求

| 项 | 要求 |
|---|---|
| 运行方式 | 服务器端处理（已定：租用云服务器）；同时提供自部署方案 |
| 单曲处理时间 | 4 分钟歌曲从上传到出谱 **< 5 分钟**；硬上限 15 分钟（超过视为失败并告知） |
| 调整响应 | 换演唱调 / 指法调 / 节奏型、简化开关等不重跑模型的操作 ≤ 5 秒出新图；粘贴歌词重新对齐 ≤ 30 秒 |
| 并发与排队 | 公共实例有队列，用户能看到预计等待时间 |
| 配额（已定） | 每用户每天 5 首；每服务器每天上限另定（公共实例上线前按算力定）；超出提示明日再来或自部署 |
| 数据保留（已定） | 原音频与分轨在处理完成后立即删除；分析结果与谱子保留 30 天供继续调整；用户可随时删除自己的数据 |
| 隐私 | 不把用户音频用于训练；不做必要运维以外的数据收集 |
| 版权 | 不分发任何音频衍生物；谱子（和弦 + 歌词 + 旋律）与现有和弦谱站同等风险水平；服务条款注明用户对上传内容负责 |
| 许可证（已定） | **MIT**。注意：代码 MIT 不等于依赖的模型权重也可随意用，选型时需逐个核对权重许可（部分为 CC-BY-NC），公共实例与自部署文档都要列出 |
| 多语言 | 界面中 / 英；歌词识别中 / 英 |
| 可观测性 | 每个任务各环节耗时、失败原因、队列长度可查 |
| 可测试性 | 和弦 / 节拍 / 调性准确率在公开数据集上有基准。只用开放许可且附音频的数据集：节拍用 GTZAN-Rhythm，和弦与调性用 GuitarSet 与 AAM（Isophonics / Beatles、RWC 不提供音频，不用） |
| 失败处理 | 任何失败都给用户可理解的原因，不静默 |

## 8. 待决策问题

阶段 1 的需求级决策已全部定稿：单曲时长上限 8 分钟；配额每用户每天 5 首；数据保留 30 天；许可证 MIT；只有发起者能调整谱子；里程碑按 5.7 的 M1 / M2 划分；简化和弦默认开。

实现层面的开放问题见 `docs/plans/frontend-discord.md` 和 `docs/plans/backend.md` 各自的"开放问题"一节。

## 9. 验收标准（阶段 1）

- 上传一首 4 分钟 mp3，5 分钟内收到四层弹唱谱 PNG + PDF。
- 和弦准确率：GuitarSet 与 AAM（抽 500 首）上 major/minor 级别均 ≥ 80%。
- 调性正确率：GuitarSet 与 AAM（同一批 500 首）上均 ≥ 85%。
- 节拍 F-measure：GTZAN ≥ 85%。
- 任意演唱调 × 指法调组合下，变调夹品数、全部和弦名、页眉 `1=X` 正确换算（单元测试覆盖 12 × 12 组合）；指法调不变、只改演唱调时，简谱数字与和弦名不变。
- 粘贴正确歌词后，行级对齐误差 ≤ 0.5 秒（抽样人工核对）。
- 切换任一选项 → 新图 ≤ 5 秒。
- 导出的 MusicXML 在 MuseScore 4 中可以直接修改单个和弦并重新排版，无需手工修补文件。
- 导出的 MusicXML 能被 MuseScore 4 打开且和弦、歌词、六线谱完整。
- 任务失败时用户收到可理解的原因。
