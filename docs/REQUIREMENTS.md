# OpenCapo 需求文档（草稿 v0.1）

> 状态：讨论中。标注 **[待定]** 的条目需要一起拍板，标注 **[建议]** 的是起草人的倾向性意见，可以推翻。

## 1. 背景与目标

市面上的"听歌扒谱"工具（Capo、Lamucal、Chordify、Moises）都是闭源收费产品，且要么只能在 Apple 生态里用（Capo），要么必须把音频上传到厂商服务器（Lamucal、Chordify、Moises）。

OpenCapo 的目标：做一个**开源、可本地运行**的替代品，覆盖这些产品的核心能力（分轨、和弦、节拍、调性、旋律、歌词、同步播放与编辑、导出），并在此基础上加入它们没有的新功能。**最终产物是一张中文吉他弹唱谱**（和弦图 + 六线谱 + 简谱 + 歌词），见第 4 节。

非目标（明确不做）：
- 段落结构自动检测（intro/verse/chorus 等）。已讨论，决定不做；用户需要分段时用循环区间或手动标记代替。
- AI 翻唱 / 换声（Lamucal 的 AI Cover）
- 歌曲库 / 社区分享 / 账号体系
- 商业化相关功能（订阅、付费墙）

## 2. 目标用户与场景

**[待定]** 主要面向哪一类用户，决定了界面和输出的优先级：

| 用户 | 典型场景 | 最关心的输出 |
|---|---|---|
| 吉他/尤克里里弹唱者 | 听到一首歌想马上弹唱 | 和弦 + 歌词对齐 + 变调夹建议 + 和弦图 |
| 键盘/钢琴伴奏者 | 给人伴奏、即兴 | 和弦（含转位、七和弦） + 调性 |
| 扒谱 / 练琴者（Capo 的核心用户） | 逐句扒 solo、riff | 分轨 + 慢放 + 循环 + 频谱 + 旋律音符 |
| 乐队排练 | 分声部练习 | 分轨 + 循环 + 节拍器 + 速度调整 |

**[建议]** 第一阶段以"吉他弹唱者 + 扒谱练琴者"为主，这是 Capo 和 Lamucal 的交集，也是开源社区里最大的群体。

## 4. 统一的输入 / 输出模型

把四家产品抽象出来，核心是同一条流水线：

```
输入音频 ──▶ 分析 ──▶ 结构化结果 ──▶ 编配 ──▶ 同步播放 / 编辑 ──▶ 导出（弹唱谱）
```

**最终产物（已定）**：一张中文吉他弹唱谱，样式以 `docs/reference/desperado-sheet.webp` 为默认排版标准。从上到下四层：和弦图、六线谱（节奏型 / 指法）、简谱（人声旋律）、歌词（音节级对齐）；页眉含速度、调号（1=X）、拍号。

其中"分析"是**转录**（忠实记录原曲有什么），"编配"是**设计**（根据和弦和节拍生成人能弹的伴奏）。两者分开建模。

### 4.1 输入

**已定**：输入为音频。

| 项 | 要求 | 优先级 |
|---|---|---|
| 本地音频文件 | mp3 / wav / flac / m4a / ogg；立体声或单声道；任意采样率 | P0 |
| 拖拽 / 文件选择 | | P0 |
| URL（YouTube 等） | **[待定]** 有法律和维护成本（下载器经常坏） | P2 |
| 麦克风录音 | | P2 |
| 视频文件（抽音轨） | | P2 |

### 4.2 分析输出（数据模型）

所有结果带时间戳，以秒为单位，和原音频对齐。

| 对象 | 字段 | 备注 |
|---|---|---|
| `Beat` | time, is_downbeat, bar_index, beat_in_bar | **已定**：做到小节 + 拍即可 |
| `Tempo` | bpm（全局） | **已定**：只要全局 BPM，不做局部速度曲线 |
| `Key` | tonic, mode(major/minor), 置信度 | **已定**：做。简谱的 1=X 和变调夹换算都依赖它 |
| `Chord` | start, end, root, quality, bass（转位）, 置信度 | 见下方"和弦（已定）" |
| `Note`（人声旋律） | start, end, pitch(MIDI), 量化后的时值（起始拍、长度、附点、连音） | **已定**：只做人声旋律；必须到音符并量化到拍网格，供简谱渲染 |
| `LyricSyllable` | start, end, text, line_index, note_ref | **已定**：中、英；**音节级**对齐（英文按音节拆 Des-pe-ra-do，中文一字一音），每个音节挂到一个音符上 |
| `Stem` | 音频文件 × {vocals, drums, bass, other, ...} | |

**和弦（已定）**：
1. **覆盖面向 Capo 看齐**：根音 12 种；性质至少覆盖大、小、7、maj7、min7、6、m6、sus2、sus4、5、dim、aug 等 14 种；**必须支持转位**（如 D/F#、G/B）。开源模型（BTC 等）的标签集已包含七和弦与转位，可行。
2. **每个和弦带置信度**，并在界面上标出低置信的和弦提醒用户复核。四家竞品都不显示置信度。
3. **和弦边界对齐到拍网格**：先检测节拍，再在拍 / 小节网格上标和弦，不输出"忽长忽短的色块"。

**旋律 + 歌词的预期**：这两项是全流程里最难的（人声滑音 / 颤音切成离散音符有损；音节对到音符两边都可能错）。原则是 **AI 出初稿，人来改**，编辑功能必须配套。歌词另提供"用户粘贴歌词文本、系统只做对齐"的模式，准确率远高于从零识别，也不受语言限制；不做自动联网抓歌词（版权）。

### 4.3 编配

把分析结果变成可弹的伴奏。全部可由用户修改。

| 项 | 规则 | 已定 / 待定 |
|---|---|---|
| 指法调与变调夹 | 用户**只选指法调**（C/G/D/A/E 等好按的调），系统按 `变调夹品数 = 原曲调 − 指法调` 算出夹几品，并给出该指法调下的和弦名与和弦图。品数 > 7 的选项排后 / 标灰。用户变调（音频移调）后自动重算。保留手动覆盖变调夹与任一和弦 | 已定 |
| 和弦指法 | 每个和弦给一个默认按法，用户可换 | 已定 |
| 节奏型 | **可选**：系统按速度 / 风格推荐一个，用户可从节奏型库（扫弦、分解等常用型）里换，也可不用 | 已定 |
| 前奏 / 间奏 | **留空**，不做乐器旋律转录；用户可手动填 | 已定 |
| 简谱 | 由人声 `Note` + `Key` 渲染为音级（1–7）+ 时值记号 | 已定 |

### 4.4 交互与播放
| 功能 | 要求 | 优先级 |
|---|---|---|
| 同步播放 | 播放头经过时高亮当前和弦 / 歌词 / 小节 | P0 |
| 变速 | 至少 50%–100% 不变调；目标 25%–150% | P0 |
| 变调 | ±12 半音，和弦标记同步换算，变调夹品数自动重算 | P0 |
| 指法调选择 | 见 4.3；一个下拉框，每项显示"X 调指法（夹 N 品）" | P0 |
| 循环 | A-B 循环，吸附到拍 / 小节 | P0 |
| 分轨混音 | 各轨独立音量 / 静音 / 独奏 | P0 |
| 和弦简化显示开关（已定） | 一键把 Cmaj7 显示为 C、G/B 显示为 G 等，底层数据不变，只改显示；小白与进阶用户共用同一份结果 | P0 |
| 低置信和弦高亮（已定） | 置信度低于阈值的和弦用不同样式标出 | P0 |
| 节拍器 | 按检测到的拍点生成 click | P1 |
| 波形 / 频谱 | 波形必须有；频谱图（Capo 的扒 solo 核心）P1 | P0 / P1 |
| 和弦图 | 吉他为主；尤克里里、钢琴 P2 | P0 |
| 弹唱谱渲染 | 界面内渲染四层弹唱谱。六线谱 / 和弦图可用 alphaTab 等开源库；**简谱主流库不支持，需自绘（SVG）** | P0 |

### 4.5 编辑
| 功能 | 优先级 |
|---|---|
| 修改单个和弦（根音、性质、低音） | P0 |
| 换和弦指法 | P0 |
| 换 / 去掉节奏型 | P0 |
| 手动覆盖变调夹品数 | P1 |
| 批量替换同一和弦 | P1 |
| 调整和弦边界（拖动） | P1 |
| 调整拍点 / 小节线 / 拍号 | P1 |
| 编辑简谱音符（音高、时值、增删） | P1 |
| 编辑歌词文本与音节对齐；粘贴歌词重新对齐 | P1 |
| 手动填写前奏 / 间奏 | P2 |
| 撤销 / 重做 | P0 |

### 4.6 导出
| 格式 | 内容 | 优先级 |
|---|---|---|
| 弹唱谱 PDF / 图片 | 默认排版标准的四层谱 | P0 |
| 项目文件（JSON） | 全部分析结果 + 编配 + 用户编辑，可重新打开 | P0 |
| MusicXML | 五线谱 + 六线谱 + 和弦符号 + 歌词音节，可导入 MuseScore / Guitar Pro 精修 | P1 |
| Guitar Pro (.gp) | 同上，面向 Guitar Pro 用户 | P2 |
| 文本 / ChordPro 和弦谱 | 和弦 + 歌词 | P1 |
| MIDI | 和弦轨 + 旋律轨 + 拍点 | P1 |
| 分轨音频 | wav / mp3 | P0（分轨本身是 P0） |

## 5. 新功能（竞品没有的）

**[待定]** 这是 OpenCapo 的差异化所在，需要你来定。几个候选方向供讨论：

已定：
- **中文弹唱谱（简谱 + 六线谱 + 歌词）一键生成**：四家竞品都不出简谱，国内平台的谱全靠人工编配。这是最大的差异点。
- **选指法调而不是选变调夹**：用户只选"用哪个调的指法弹"，变调夹品数和和弦自动算出。
- **可解释 / 可信度**：每个和弦给置信度，低置信的高亮提示用户复核（竞品都不显示）。
- **简化和弦显示开关**：一键把 maj7 / sus / 转位等简化成三和弦，给初学者；竞品没有做成开关。
- **粘贴歌词对齐模式**：用户贴歌词，系统只做对齐，绕开 ASR 准确率问题。

候选：
- **本地优先 + 隐私**：全部在用户机器上跑，不上传。这本身已是对四家竞品的差异化。
- **多版本对比**：同一首歌跑多个和弦模型，并排显示分歧处。
- **练习模式**：对用户选定的循环区间逐步提速练习（不依赖段落检测）。
- **和 DAW / 乐谱软件联动**：导出 MusicXML、REAPER 工程等。
- **批处理 / CLI**：整个文件夹批量分析，给研究者和教师用。
- **插件化模型**：分轨、和弦、节拍模型可替换，方便社区接入新模型。

## 6. 非功能需求

| 项 | 要求 |
|---|---|
| 运行位置 | **[建议]** 默认完全本地；可选自建服务端供弱设备使用 |
| 硬件 | **[待定]** 目标是"笔记本 CPU 可用，GPU 加速"还是"必须 GPU"？影响模型选型 |
| 性能 | **[建议]** 一首 4 分钟歌曲，CPU 上全流程 < 3 分钟，GPU 上 < 30 秒 |
| 平台 | **[待定]** 见第 8 节 |
| 许可证 | **[待定]** 需与依赖兼容（Demucs MIT、WhisperX BSD、madmom BSD、部分模型权重为 CC-BY-NC） |
| 离线可用 | 模型下载后无需联网 |
| 隐私 | 不上传音频、不收集遥测 |
| 可测试性 | 和弦 / 节拍 / 调性准确率在公开数据集上有基准（Isophonics/Beatles、RWC、GTZAN-Rhythm 等） |

## 7. 架构约束（初步）

**[建议]** 分三层，彼此可独立使用：

1. **核心库**（Python）：音频 → 结构化结果。模型可插拔。这一层是所有东西的基础，也最容易先做出来验证效果。
2. **CLI**：`opencapo analyze song.mp3 --out song.json`，批处理、脚本化。
3. **界面**：**[待定]** Web 前端（本地起服务，浏览器访问）/ 桌面应用（Tauri/Electron）/ 两者。

候选开源组件（均已有权重、许可证明确）：

| 环节 | 候选 |
|---|---|
| 分轨 | Demucs (HTDemucs)、BS-RoFormer |
| 节拍 / 强拍 | all-in-one (mir-aidj)、Beat This!、madmom |
| 和弦 | BTC、ChordFormer、autochord；或基于 all-in-one 的扩展 |
| 调性 | 基于和弦统计的规则法 + 模型（如 essentia 的 key extractor） |
| 旋律 / 音高 | RMVPE、CREPE、basic-pitch |
| 歌词识别 + 对齐 | WhisperX（faster-whisper + wav2vec2 对齐）；中文对齐模型需单独评估；英文音节切分用 pyphen / CMUdict |
| 制谱渲染 | 六线谱 / 和弦图：alphaTab（浏览器内渲染，读写 Guitar Pro）或 Verovio（MusicXML → SVG）；简谱：自绘 SVG；交换格式 MusicXML（music21 生成） |
| 音频变速变调 | Rubber Band、SoundTouch、librosa |

## 8. 待决策问题

1. **产品形态**：Web 前端（本地服务）/ 桌面应用 / 先做核心库 + CLI 再定界面？
2. **算力假设**：纯 CPU 必须可用？还是默认有 GPU？
3. **第一阶段的目标用户**：吉他弹唱 / 扒 solo / 键盘 / 乐队？
4. **输入源**：是否支持 YouTube 链接？
5. **新功能**：第 5 节里哪些要做？你心里有没有别的想法？
6. **许可证**：MIT / Apache-2.0 / GPL？
7. **语言**：核心库 Python 基本没有争议；前端用什么？
8. **分阶段顺序** **[建议，待确认]**：
   - **阶段 1**：音频 → 分轨 + 节拍 + 和弦 + 调性 → 指法调选择 + 节奏型 + 歌词（粘贴对齐优先，ASR 其次）→ 三层弹唱谱（和弦图 + 六线谱节奏型 + 歌词），无简谱行。这已达到 Ultimate Guitar / 国内多数和弦谱的水平。
   - **阶段 2**：加人声旋律 → 简谱行 + 歌词音节对齐到音符，补齐四层。
   - **阶段 3**：MusicXML / Guitar Pro 导出、频谱图、练习模式等。

## 9. 验收标准（MVP 草案）

- 任意 mp3 拖进去，无需联网，能得到分轨 + 和弦 + 节拍 + 调性。
- 和弦准确率：在 Isophonics Beatles 数据集上 major/minor 级别 ≥ 80%（与 2020 年后的公开模型持平）。
- 节拍 F-measure：GTZAN 上 ≥ 85%。
- 同步播放时，和弦高亮与音频偏差 ≤ 50 ms。
- 变速到 50% 时不变调，且无明显金属音。
- 用户改一个和弦后导出，重新打开结果一致。
